Intégrer misfits.ai Mail dans votre application

Ce guide s'adresse aux développeurs qui souhaitent envoyer, recevoir et lire des e-mails via misfits.ai Mail. Il présente les protocoles standards (SMTP, IMAP), l'API publique de haut niveau et les principes d'authentification, sans référence à l'infrastructure interne.

1. Présentation

Qu'est-ce que misfits.ai Mail et à qui s'adresse cette documentation.

Un service e-mail programmable

misfits.ai Mail expose une plateforme de messagerie compatible avec les standards SMTP et IMAP, complétée d'une API publique pour intégrer l'envoi et la lecture dans vos applications.

Public visé

Développeurs qui construisent un client, un backend ou un automatisme au-dessus de misfits.ai Mail. Aucun accès administrateur n'est requis pour suivre ce guide.

2. Envoyer un e-mail

Utilisation du protocole SMTP standard.

SMTP compatible

Configurez votre client ou votre bibliothèque (Nodemailer, lettre, JavaMail, etc.) avec les identifiants qui vous ont été fournis. STARTTLS et l'authentification par mot de passe sont pris en charge selon les usages standards.

STARTTLS AUTH LOGIN MIME

Bonnes pratiques

  • Renseignez un From valide au domaine autorisé.
  • Ajoutez Message-Id et Date.
  • Utilisez multipart/alternative pour joindre HTML + texte.
  • Respectez les politiques SPF/DKIM/DMARC de votre domaine.

3. Recevoir et lire

Deux voies : IMAP standard ou API publique de haut niveau.

Via IMAP

Tout client compatible IMAP (Thunderbird, mutt, imapclient, etc.) peut se connecter avec les identifiants du compte. Les dossiers standards (INBOX, Sent, Drafts, Trash) sont exposés.

Via API publique

L'API HTTP expose des opérations de haut niveau : lister les messages d'un dossier, récupérer un message par identifiant, marquer lu/non-lu, déplacer, supprimer. Elle renvoie du JSON et suit une convention REST.

Opérations typiques

  • Lister les messages d'un dossier avec pagination.
  • Récupérer un message : en-têtes, corps HTML/texte, pièces jointes.
  • Mettre à jour les flags (lu, favori, archivé).
  • Envoyer un message via l'endpoint dédié (alternative à SMTP).

L'URL de base et la liste exhaustive des routes vous sont communiquées à l'activation de votre compte intégrateur.

4. Sécurité & authentification

Comment vos requêtes API sont identifiées.

En-tête d'identification

Chaque appel API porte un en-tête d'identification utilisateur (par convention x-user-id) que votre backend ajoute à partir de la session authentifiée de l'utilisateur final. Les valeurs concrètes ne sont jamais codées en dur côté client.

Transport

  • HTTPS obligatoire pour l'API.
  • TLS pour SMTP et IMAP.
  • Ne pas stocker les identifiants en clair côté client.

Modèle d'autorisation

Un utilisateur ne peut lire et manipuler que ses propres messages. Les routes d'administration ne font pas partie de cette documentation intégrateur.
